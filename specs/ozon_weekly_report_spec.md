# ТЗ: Ozon Weekly Sales Report (MD версия)

## Задача

Добавить в проект новый отдельный отчёт **Ozon Weekly Sales Report** в формате XLSX по образцу `weeks-report.xlsx`. Отчёт должен строиться по неделям, содержать товарную иерархию из 1С, недельные показатели продаж и выкупов, остатки Smile/FBO и динамику по неделям.[file:10][file:5]

## Область изменений

Изменения делать **только для Ozon**. Не менять и не рефакторить WB-код (`mgr-wb.js`, `ffl-wb.js`) без прямой необходимости.[file:1][file:5]
Не ломать существующие Ozon-отчёты:
- `fulfillmentReport()` из `ffl.js`;[file:1]
- `managementReport()` из `mgr.js`.[file:5]

## Архитектура и новые файлы

Создать новый модуль, например `weeks-ozon.js`.

В нём реализовать:
- `calculateWeeklySalesData(weeksCount = 13, endDate = yesterday)`;
- `weeklySalesReport(weeksCount = 13, endDate = yesterday)`.

Стиль файла должен повторять существующие Ozon-модули: отдельный расчёт данных, отдельная генерация XLSX, отдельный CLI entrypoint.[file:1][file:5]

## Источники данных

Использовать существующие сервисы и паттерны:[file:1][file:5]

- `ozon.getAllFboOrders(fromDate, toDate)` — основной источник заказов для weekly report.
- `ozon.getAllFbsOrders(fromDate, toDate)` — подключать только при явной необходимости.
- `ozon.getAllStocks()` — источник текущих FBO stock data.
- `ozon.getClustersAndWarehouses()` и `ozon.createWarehouseToClusterMap(...)` — при необходимости кластерной детализации.
- `ozon.getAllProducts()` — имена товаров.
- `oneC.getStock()` — 1С-иерархия и остаток Smile.

Из 1С подтягивать:[file:5]
- `Price`, `CenaSeb`, `Amount`, `Brand`, `Group`, `Subgroup`.

Маппинг с 1С выполнять по аналогии с `merge1CStock` в `mgr.js`, где данные 1С маппятся по `Articul` к `offer_id`, добавляя `price_1c`, `cost_1c`, `brand`, `group`, `subgroup`.[file:5]

## Формат отчёта

### Левая товарная часть

Первые 6 колонок:
- `Артикул Родитель`;
- `Наименование родитель`;
- `Подгруппа`;
- `Бренд`;
- `Группа`;
- `Наименование`.[file:10]

### Критически важное требование по артикулу

`Артикул Родитель` **обязан** быть базовым артикулом **без размера**. В примере weekly report в первой колонке используется parent/base article без size suffix, например `D81250`.[file:10]

Правило:
- если внутренний SKU/вариант выглядит как `D81250-L`, `D81250-XL`, `D81250-XXL`, то в `Артикул Родитель` писать только `D81250`;
- размер нельзя включать в `Артикул Родитель`;
- размерный вариант допускается только в `Наименование` или во внутреннем техническом ключе (например, `offer_id`).[file:10]

Если у Ozon нет отдельного поля parent, нужно вычислять `parent_article` через нормализацию SKU и safe fallback, но в итоговом XLSX `Артикул Родитель` всегда без размера.[file:10]

### Имена

- `Наименование` — имя конкретного варианта/SKU из каталога Ozon или из order data.[file:1][file:5]
- `Наименование родитель` — общее имя модели:
  - если явный parent есть — использовать его;
  - иначе нормализованное имя без размерного хвоста;
  - если не удаётся — брать первое имя в группе `parent_article`.[file:10]

### Недельные блоки

Для каждой недели — отдельный блок с merged header вида `НЕДЕЛЯ 1 (29.12.25-04.01.26)`, `НЕДЕЛЯ 2 (05.01.26-11.01.26)` и т. д.[file:10]

Внутри блока 10 колонок:
- `Сумма заказов`;
- `Количество заказов шт`;
- `Выкупы сумма`;
- `Выкупы кол-во`;
- `% сумма`;
- `% выкупы`;
- `Остаток склад Смайл`;
- `Остаток FBO`;
- `Средняя цена недели`;
- `Средняя цена недели %`.[file:10]

## Периодизация

### Недели

Отчёт строится по `weeksCount` полным неделям назад от `endDate`. Неделя = понедельник–воскресенье. Подписи недель должны быть логически совместимы с примером `weeks-report.xlsx`.[file:10]

### Параметры

Поддержать параметры:
- `weeksCount` (по умолчанию 13);
- `endDate` (по умолчанию вчера).

## Ключ группировки

Внутренний технический ключ — `offer_id`, так как текущие Ozon-отчёты уже строятся вокруг `offer_id` и merge с 1С выполняется по нему.[file:1][file:5]

Строка отчёта выводит `parent_article` без размера в колонке `Артикул Родитель`.[file:10]

## Метрики

### 1. Сумма заказов

`Сумма заказов` = сумма стоимости заказанных единиц за неделю.[file:10]

### 2. Количество заказов шт

`Количество заказов шт` = суммарное количество единиц товара за неделю, а не число строк/документов.[file:10]

### 3. Выкупы сумма

`Выкупы сумма` = сумма реально выкупленных / доставленных / финализированных продаж за неделю.[file:10]

### 4. Выкупы кол-во

`Выкупы кол-во` = количество реально выкупленных единиц за неделю.[file:10]

### 5. Определение «выкуп»

Так как в текущих `ffl.js` и `mgr.js` нет готовой weekly-логики выкупов, нужно:
- определить статус/событие в Ozon API, соответствующее «выкупу»;
- реализовать отдельную функцию, которая фильтрует заказы по этому признаку;
- задокументировать это решение в комментарии.

Если API не даёт надёжного weekly buyout signal:
- не подменять выкуп обычным заказом молча;
- использовать только явно задокументированный fallback или оставить buyout-поля пустыми.[file:1][file:5][file:10]

### 6. Остаток склад Смайл

`Остаток склад Смайл` брать из 1С поля `Amount`, как в текущих Ozon-скриптах.[file:1][file:5]

Если нет исторических weekly snapshots 1С:
- использовать текущее `Amount` как snapshot для всех недель;
- явно описать ограничение (комментарий / hidden sheet `Meta`).[file:10]

### 7. Остаток FBO

`Остаток FBO` считать на базе `ozon.getAllStocks()` по логике `mgr.js`:

- `free_to_sell_amount + reserved_amount + promised_amount`.[file:5]

Если нет исторических FBO snapshots:
- использовать текущий snapshot для всех недель;
- явно задокументировать ограничение.[file:5][file:10]

### 8. Средняя цена недели

Правило:
- если `buyout_qty > 0`: `avg_week_price = buyout_amount / buyout_qty`;
- иначе, если `order_qty > 0`: `avg_week_price = order_amount / order_qty`;
- иначе `null`.[file:10]

### 9. Процентные изменения

Начиная со 2-й недели:
- `% сумма` = `(current.order_amount - prev.order_amount) / prev.order_amount`;
- `% выкупы` = `(current.buyout_amount - prev.buyout_amount) / prev.buyout_amount`;
- `Средняя цена недели %` = `(current.avg_week_price - prev.avg_week_price) / prev.avg_week_price`.[file:10]

Если в предыдущей неделе база = 0 или `null` — выводить пусто.

## Формат результата calculateWeeklySalesData

Функция должна вернуть структуру, пригодную для Excel builder, например:

```js
{
  weeks: [
    {
      index: 1,
      label: 'НЕДЕЛЯ 1 (29.12.25-04.01.26)',
      fromDate: '2025-12-29T00:00:00.000Z',
      toDate: '2026-01-04T23:59:59.999Z'
    }
  ],
  items: [
    {
      offer_id: 'D81250-L',
      parent_article: 'D81250',
      parent_name: 'Комбинезон HD S-XXL',
      subgroup: 'серия HD',
      brand: 'DOWELL',
      group: 'Средства индивидуальной защиты',
      name: 'Комбинезон рабочий HD, L',
      weeks: [
        {
          order_amount: 500200,
          order_qty: 61,
          buyout_amount: 319584,
          buyout_qty: 39,
          order_amount_pct: null,
          buyout_amount_pct: null,
          smile_stock: 841,
          fbo_stock: 1152,
          avg_week_price: 8194.46,
          avg_week_price_pct: null
        }
      ]
    }
  ],
  fromDate,
  toDate
}
```

Важно: внутренний `offer_id` может содержать размер, но `parent_article` для вывода в отчёте — всегда без размера.[file:10]

## Excel builder

В `services/excel` добавить новый метод, например `createOzonWeeklySalesReportBuffer(data, options)`.[file:1][file:5]

### Требования к XLSX

- Один лист `Отчёт`.
- Две строки заголовков:
  - верхняя — merged headers по неделям;
  - нижняя — названия полей внутри недельного блока.
- Первые 6 колонок — товарная часть (`Артикул Родитель`, `Наименование родитель`, `Подгруппа`, `Бренд`, `Группа`, `Наименование`).[file:10]
- Freeze panes по строкам заголовка и левой части.
- Автофильтр на строке подзаголовков.
- Читаемые ширины колонок.
- Форматирование чисел:
  - суммы — с разделителем тысяч;
  - количества и остатки — integer;
  - проценты — процентный формат;
  - средняя цена — 0 или 2 знака после запятой.[file:10]

Визуально и логически XLSX должен быть максимально близок к `weeks-report.xlsx`, но без необходимости побитового совпадения стилей.[file:10]
